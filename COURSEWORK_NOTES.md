# Пояснения к курсовой работе

## 1. Что делает приложение

Osteria Verde — веб-приложение для онлайн-бронирования столиков. Посетитель выбирает дату, время, количество гостей и желаемое расположение. Сервер проверяет базу данных, предлагает подходящий свободный столик и создаёт бронь. После этого пользователь получает уникальный номер, по которому можно посмотреть или отменить бронь.

Бронь занимает два часа. Например, бронь на 18:00 пересекается с бронью на 19:30, но не пересекается с бронью на 20:00. Отменённые брони больше не занимают столик.

## 2. Технологии и их назначение

- **React** создаёт интерфейс из компонентов и обновляет его без перезагрузки страницы.
- **TypeScript** описывает типы формы, ответа сервера и данных о доступности.
- **Vite** запускает frontend в режиме разработки и собирает production-версию.
- **CSS** отвечает за зелёно-бежевое оформление и адаптацию под телефон.
- **Spring Boot** запускает сервер и предоставляет REST API.
- **Spring Data JPA** связывает Java-классы Reservation и RestaurantTable с таблицами базы данных.
- **PostgreSQL** хранит столики и бронирования.
- **Docker Compose** запускает PostgreSQL с одинаковыми настройками на разных компьютерах.

Дополнительная библиотека управления состоянием не используется: для такого размера проекта достаточно useState, props и обычных функций.

## 4. Как React взаимодействует со Spring Boot и PostgreSQL

Функции из frontend/src/api.ts вызывают REST API через fetch. Во время разработки Vite перенаправляет адреса /api на http://localhost:8081.

Spring Boot получает JSON или параметры запроса в ReservationController, передаёт их в ReservationService, а сервис обращается к JPA-репозиториям. Hibernate преобразует эти действия в SQL-запросы к PostgreSQL. Ответ снова преобразуется в JSON и возвращается в React.

~~~text
React → HTTP-запрос → Spring Controller → Service → JPA → PostgreSQL
React ← JSON-ответ  ← Spring Controller ← Service ← JPA ← PostgreSQL
~~~

## 5. Бронирование по шагам

1. Пользователь выбирает дату, время, количество гостей и расположение.
2. React отправляет запрос проверки доступности.
3. Backend валидирует данные и получает столики нужной вместимости.
4. Для каждого столика проверяется пересечение с подтверждёнными бронями.
5. Если столик найден, форма открывает ввод имени, телефона и email.
6. При подтверждении сервер повторяет проверку, блокируя подходящие строки столиков на время операции. Это не позволяет двум одновременным запросам занять один столик.
7. Сервер сохраняет бронь со статусом CONFIRMED и создаёт номер OV-XXXXXX.
8. React показывает номер, дату, время и назначенный столик.

Повторная проверка на шаге 6 обязательна: между предварительной проверкой и нажатием кнопки другой пользователь мог занять столик.

## 6. Основные компоненты и функции

- BookingForm хранит значения полей, проверяет доступность и отправляет бронь.
- BookingConfirmation показывает результат и позволяет отменить бронь.
- ReservationLookup ищет бронь по номеру.
- ReservationDetails повторно используется в подтверждении и поиске.
- ReservationService.create валидирует запрос, выбирает столик и сохраняет бронь.
- ReservationService.findAvailableTable сортирует подходящие столики и исключает занятые.
- ReservationRepository.countOverlapping проверяет пересечение временных интервалов.
- TableDataInitializer добавляет исходный список столиков при пустой таблице.

## 7. Код для курсового отчёта

Для листингов и объяснения лучше всего подходят:

1. тип ReservationRequest на frontend — пример использования TypeScript;
2. handleCheck и handleSubmit в BookingForm.tsx — обработка событий и запросов;
3. функция request в api.ts — единая обработка HTTP-ответов и ошибок;
4. сущности Reservation и RestaurantTable — связь Java-классов с базой;
5. запрос countOverlapping — проверка занятости интервала;
6. метод ReservationService.create — основной сценарий бронирования;
7. медиазапросы в styles.css — адаптивная вёрстка.

Не стоит вставлять в отчёт целые файлы. Для каждого фрагмента достаточно 10–30 строк и короткого пояснения.

## 8. Какие скриншоты сделать

1. Главная страница на компьютере.
2. Форма с выбранными датой, временем и количеством гостей.
3. Сообщение «Свободный столик найден».
4. Экран успешного подтверждения с номером брони.
5. Результат поиска брони по номеру.
6. Сообщение об отсутствии свободного столика.
7. Ошибка при неверных данных или прошедшей дате.
8. Мобильная версия страницы в инструментах разработчика браузера.
9. Таблицы restaurant_tables и reservations в PostgreSQL, если используется pgAdmin или консоль.

Перед скриншотами следует запустить весь проект и создать тестовые данные с вымышленными контактами.
